# Professional email 中文→英文独立策略：实现与范围

本轮仅修改代码和验证，不更新正式版本、Release 或自动更新。基线为正式版 1.1.2。新分支标识为 `customer-email-zh-en/v1`，是尚未发布的策略版本；开发中各轮以 manifest 的代码哈希区分，不能把先前结果冒充最终代码结果。

## 处理流程

原始请求正文保留在 `body.text` → 仅此模式/方向选择 `protectEmail` → 独立英文忠实翻译提示与结构化 schema → 单次常规模型响应中的 Translation、Source notes、状态 → 恢复受保护实体 → 以原文做有限事实检查 → 必要时最多一次定向修复 → 独立展示及历史保存。

没有先润色中文，没有让回译成为事实依据，没有额外常驻模型审查。模型生成的 Source notes 不是独立验证证据。原文数字矛盾不使翻译失败；例如 18 必须保留，独立英文提示解释计算差异。所有阶段只保存本次合成测试，配置密钥不进入 trace。无译文结果缓存；模型选择缓存只用于供应商可用性，不缓存邮件内容或跨模式复用译文。历史去重包含模式、方向和策略版本。

## 能力边界（不是“全部语义已验证”）

本地解析保存数值、币种、raw、start/end 和附近语境；BigInt 十进制用于金额及受支持的差额计算。它不是完整金融语义解析器：本金/利息的明确紧邻表述、部分第一人称付款方向有检查，任意第三方人物关系、复杂多币种归属、否定范围、正负盈亏、日期时区和边界条件主要仍依赖模型忠实翻译与逐条语义评审。不能把数字集合相同视为这些关系全部通过。

注入测试明确显示：本金1000/利息20互换、我给David付款变成我收到款可检出；David给Sarah付款变成Sarah给David付款不能可靠自动检出。此漏检保留为测试中的已知边界，没有添加无上下文姓名替换规则。币种省略未独立验证时不会宣称数值已验证；未支持的表达也不保证均能自动发现。

Source notes 的英文、确切原文片段及结构可检查，但完整意义仍可能被模型误判。首轮66正是反例；不能把模型自己生成的提示当成真实来源矛盾。系统不对普通错别字逐条报警；本次报告另外计入多余提示与错误提示。
